## 1. 目的與邊界

### 目的
定義第一版「出征契約」本輪可被工程依賴之 lock 規格：一次派出的邊界、狀態、正式結果、不可洗白、模擬源可稽核、成長只錨定證據。  
32 必填欄位必須存在且結算閘可檢查；數值預設（本金／秒數）標後補，不阻擋開工。

### 短征定義（D11）
- **短征**：同輪體驗內可見歸來。
- 允許壓縮／加速模擬，以對齊 60 秒節奏。
- 戰報仍必須標模擬源；禁止暗示真資。

### 第一版切什麼
- 自行部署策略 Agent → 模擬出征 → 戰報 → 續用或撤回（D1、D2）
- 自建模擬盤；OKX 僅參考雛形，**不做** OKX 串接依賴（D3）
- 帝國首頁、具名 Agent（例：WOLF）、可派→出征中→已歸來、戰績牆
- 成長＝可信證據／履歷變多（D4）
- 歷史戰績與失敗紀錄不可洗白（D5）
- 最薄競技對照（非主循環）

### 第一版不切什麼
- 虛構 XP／等級／任務清單當成長主軸
- 工具箱／手動下單主路徑
- OKX API 接線、真實資金、跟單經濟、排行榜主循環
- 市場雇佣他人 Agent
- 賽季重置清歷史
- 作戰中取消入口（`cancel_supported=false`）
- 同 Agent 並行多契約（`parallel_dispatch_allowed=false`）

### 60 秒句（驗收對齊）
「我有一座 AI 交易帝國，我剛派 WOLF 出去，它賺了錢回來。」  
硬標準 D6：60 秒內理解成立＋自願再次出征。

## 2. 出征契約欄位

### 2.1 本輪 32 必填（LOCK）

採納待填表「建議必填候選＝是」32 項。欄位必須存在；結算閘須能檢查。  
`planned_duration`／`simulation_principal`：**欄位必有，數值後補**（不得寫死舊閉環秒數／grace／stake）。

| 欄位名 | 用途 | 結算閘檢查要點 |
|---|---|---|
| `contract_id` | 單次出征契約唯一識別 | 非空；本輪內唯一 |
| `empire_id` | 歸屬哪一座帝國 | 非空；與派出者帝國一致 |
| `agent_id` | 派出哪位具名 Agent | 非空；Agent 存在且可派 |
| `strategy_version` | 本次綁定策略／配置版本 | 非空；派出後不可熱改寫本契約綁定 |
| `simulation_principal` | 本次模擬本金（非真資） | 欄位存在；數值後補後須為正數模擬單位 |
| `currency` | 績效金額單位標示 | 非空；與本金同一模擬單位 |
| `time_window_type` | 時窗類型（固定時長／結束條件／併用） | 非空；本輪至少支援固定時長 |
| `planned_duration` | 計劃出征時長 | 欄位存在；數值後補；短征允許壓縮模擬對齊體驗 |
| `simulation_source` | 模擬源可稽核結構 | 非空；可指向引擎／資料集／版本／run |
| `sim_engine_id` | 自建模擬引擎識別 | 非空 |
| `market_dataset_id` | 行情／資料集識別 | 非空 |
| `market_dataset_version` | 資料集版本 | 非空 |
| `sim_run_id` | 單次模擬執行 id | 非空；可與 evidence／battle_result 對齊 |
| `status` | 契約生命週期狀態 | 合法枚舉；轉移見 §3 |
| `created_at` | 契約建立時間戳 | 非空 |
| `dispatched_at` | 實際派出時間戳 | 進入 `in_field` 後非空 |
| `settled_at` | 結算完成時間戳 | 進入 `returned` 後非空 |
| `battle_result_id` | 指向正式戰報 | 歸來後非空（含失敗結局） |
| `result_status` | 正式結果結局態（含失敗類） | 有結果時非空；失敗併入本欄 |
| `realized_pnl` | 已實現損益（模擬單位） | 正式結果必有；無成交可為 0 |
| `return_pct` | 報酬率 | 正式結果必有；分母規則後補但欄位必填 |
| `max_drawdown` | 最大回撤（績效語彙） | 正式結果必有 |
| `trade_count` | 成交／交易次數 | 正式結果必有；≥0 |
| `attribution_ref` | 歸因最低可稽核引用 | 正式結果必有 |
| `constraint_snapshot` | 派出當下約束不可變快照 | 派出後非空（可極薄） |
| `evidence_id` | 不可變證據錨點 | 正式結果必有 |
| `is_official` | 是否為戰績牆正式列 | 預設 false；僅通過結算閘可 true |
| `replay_ok` | 重播一致性校驗通過 | 正式列要求 true；未過不得 `is_official=true` |
| `parallel_dispatch_allowed` | 同 Agent 可否並行多契約 | 本輪鎖定 `false`（單線） |
| `cancel_supported` | 作戰中可否經營者取消 | 本輪鎖定 `false` |
| `okx_dependency` | 是否依賴 OKX 串接 | 本輪鎖定 `false` |
| `real_funds` | 是否真資 | 本輪鎖定 `false` |

### 2.2 選填／後補（非本輪必填）

| 欄位名 | 狀態 | 備註 |
|---|---|---|

| `leaderboard_score` | **禁止主循環** | 不作出征主路徑 |

## 3. 狀態機

### 產品對齊（最小）
可派／出征中／已歸來。

### 內部建議枚舉（本輪可實作）
| 內部 | 產品語意 | 本輪 |
|---|---|---|
| `ready` | 可派 | 必有 |
| `in_field` | 出征中 | 必有 |
| `returned` | 已歸來 | 必有 |

`draft`／`archived`：本輪非必填；工程可不實作。

### 合法轉移
| 從 | 到 | 含義 |
|---|---|---|
| `ready` | `in_field` | 派出 |
| `in_field` | `returned` | 結算歸來（含賺／賠／失敗類結局） |
| `returned` | （新契約）`ready` | **再派＝新契約實例**，非改寫舊結果 |

### 本輪不做
- **cancel 路徑**：無 `in_field` → 取消態；無取消入口 UI／API。
- **並行**：`parallel_dispatch_allowed=false`；同 Agent 已有 `in_field` 契約時拒絕再派。

### 單線約束
同一 `agent_id` 同時最多一個 `in_field` 契約。再派必須等前約 `returned`。

## 4. BattleResult（正式結果）

### 角色
`BattleResult`＝單次出征的**正式結果**。結算後寫入戰績牆／履歷。  
模擬過程暫態數字**不是**正式結果。

### 失敗態（D11）
- 失敗併入 `result_status`（枚舉可含正常結算與失敗類）。
- `failure_class` **非必填**，可不實作。
- 虧損可為正式結果；失敗結局仍產 `battle_result_id`，仍受不可洗白約束。

### 必填績效欄（結算閘）
`realized_pnl`、`return_pct`、`max_drawdown`、`trade_count`，加上 `result_status`、`battle_result_id`、`evidence_id`、`attribution_ref`、`is_official`、`replay_ok`。

### 模擬 vs 正式結果邊界
| | 模擬過程 | 正式結果 |
|---|---|---|
| 進戰績牆主列 | 否 | 是（通過結算閘） |
| 當成長證據 | 否 | 是（且須可稽核） |
| 標示 | 「模擬中」可顯示 | 必須標模擬源；禁止暗示真資 |
| 改寫 | 暫態可丟 | 正式列資料層禁止洗白（§5） |

禁止：Agent 自報績效當正式結果；無模擬源之數字當正式結果。

## 5. 不可洗白（D5）

### 資料層（禁止）
- 刪除或覆寫歷史正式戰績／失敗紀錄
- 賽季或活動重置清空履歷
- 事後把虧損改為「未發生」或改寫金額／結局態
- 用展示文案覆蓋資料真相

### 展示層（允許）
- 排序、篩選、摺疊、摘要標籤
- 敘事語氣改寫（世界敘事負責），但必須仍可點回真實數字與結局
- 「精選」視圖；精選不得隱藏「失敗仍存在」的事實入口

### 原則一句
履歷變厚＝成長可見；失敗仍在。

## 6. 模擬源標示＋短征壓縮（D2、D3、D11）

- 每次正式結果必須帶可稽核之 `simulation_source`（含 `sim_engine_id`／`market_dataset_id`／`market_dataset_version`／`sim_run_id`）。
- 同重播鍵重放，正式績效數字必須一致；否則不得 `is_official=true`。
- UI／戰報必須可見「模擬」標示；禁止默默當真資結果。
- **短征**：允許壓縮／加速模擬，使同輪體驗內可見歸來；戰報仍標模擬源。
- 第一版自建模擬；`okx_dependency=false`。OKX 對照文件僅機制參考，非本契約資料源。

## 7. 成長錨定（D4）

### 只允許
- 可稽核之正式 `BattleResult` 累積
- 履歷條目變多、失敗保留、策略版本可追溯

### 禁止
- 虛構 XP、憑空等級、與績效脫鉤之任務點數當核心成長
- `xp_awarded` 欄位
- 排行榜主循環
- 用未結算暫態或自報數字當成長證據

爭議時：數字若憑空而發，重做（底線原則）。

## 8. 驗收對照

### 對 D6／再派／短征
| 檢查 | 規則側要支撐什麼 |
|---|---|
| 60 秒句成立 | 契約邊界清楚；可派→出征中→已歸來可辨；戰果有可說數字＋模擬標 |
| 短征 | 同輪體驗內可見歸來；壓縮模擬允許；模擬源仍標 |
| 自願再派 | `returned` 後開**新契約**再派；或明確撤回；決策落在續用／撤回 |
| No-go | 僅演示可跑、像工具箱、像跟單圍觀、無再派意願 → 規則不得為「跑通」放行假戰績 |

### 對五感驗收（規則相關列）
| 感 | 規則對照 |
|---|---|
| 任命感 | 契約綁 `agent_id`＋`strategy_version`；非參數面板主路徑 |
| 出征感 | 狀態機「出征中／已歸來」可辨；單線 |
| 戰報感 | 正式結果績效語彙＋模擬源 |
| 履歷感 | 戰績牆保留至少兩次；失敗不可洗 |
| 再派感 | 歸來後合法下一步＝再派（新契約）或撤回 |

驗收由產品主編依 D6 判決；本檔可被工程依賴欄位與結算閘。
