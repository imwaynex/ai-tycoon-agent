## 1. 目的與邊界

### 目的
定義第一版「出征契約」的最小規則骨架：一次派出的邊界、狀態、正式結果、不可洗白、模擬源可稽核、成長只錨定證據。  
讓工程能實作骨架；讓未 lock 項集中於待填表，不需猜測章節結構。

### 第一版切什麼
- 自行部署策略 Agent → 模擬出征 → 戰報 → 續用或撤回（D1、D2）
- 自建模擬盤；OKX 僅參考雛形，**不做** OKX 串接依賴（D3）
- 帝國首頁、具名 Agent（例：WOLF）、出征→作戰中→歸來→戰果、戰績牆
- 成長＝可信證據／履歷變多（D4）
- 歷史戰績與失敗紀錄不可洗白（D5）
- 最薄競技對照（非主循環）

### 第一版不切什麼
- 虛構 XP／等級／任務清單當成長主軸
- 工具箱／手動下單主路徑
- OKX API 接線、真實資金、跟單經濟、排行榜主循環
- 市場雇佣他人 Agent
- 賽季重置清歷史

### 60 秒句（驗收對齊）
「我有一座 AI 交易帝國，我剛派 WOLF 出去，它賺了錢回來。」  
硬標準 D6：60 秒內理解成立＋自願再次出征。

## 2. 出征契約欄位（最小集合骨架）

> 欄位**未 lock**。下表只列建議最小集合：欄位名＋用途一句。必填／選填／未决標清楚。細項、預設、爭議見 `出征契約-待填欄位表-草案.md`。  
> **禁止**把舊閉環欄位名當作已定規則複製進來。

| 欄位名（建議） | 用途（一句） | 必填／選填／未决 |
|---|---|---|
| `contract_id` | 單次出征契約唯一識別 | 建議必填；命名規則未决 |
| `empire_id` | 歸屬哪一座帝國 | 建議必填 |
| `agent_id` | 派出哪位具名 Agent | 建議必填 |
| `strategy_version` | 本次綁定的策略／配置版本，供歸因與重播 | 建議必填；版本格式未决 |
| `simulation_principal` | 本次模擬本金（非真資） | 建議必填；單位／上限未决 |
| `time_window` | 出征時窗或結束條件（擇一或併用） | 建議必填；表達式未决 |
| `risk_constraints` | 風險約束快照（可極薄） | 建議選填→第一版是否強制未决 |
| `simulation_source` | 模擬源可稽核標示（引擎／資料集／版本） | 建議必填；結構未决 |
| `status` | 契約生命週期狀態 | 建議必填；枚舉見 §3，轉移未决 |
| `created_at` / `dispatched_at` / `settled_at` | 狀態時間戳，供履歷與稽核 | 建議必填集合；時區與精度未决 |
| `battle_result_id` | 歸來後指向正式戰報 | 歸來後建議必填；產生時機未决 |
| `evidence_id` | 不可變證據錨點（重播／稽核） | 建議必填；內容與儲存未决 |

未 lock 的欄位**不要**寫成驗收條件。工程實作骨架時以「有欄位位址＋待填表問題句」為準。

## 3. 狀態機（建議最小）

### 建議狀態（最小）
| 狀態 | 含義 | 備註 |
|---|---|---|
| `draft` | 契約已建、尚未派出 | 是否需要此態：未决 |
| `ready` | 可派出 | 與 `draft` 合併與否：未决 |
| `in_field` | 作戰中（已派出、未結算） | 建議必有 |
| `returned` | 已歸來、正式結果已掛上 | 建議必有 |
| `archived` | 僅展示／履歷保留，不再續派此契約實例 | 是否需要：未决 |

命名可改；**未 lock**。舊閉環之 `in_progress`／`completed` 等枚舉為**非準據**。

### 建議合法轉移
| 從 | 到 | 含義 | 未决？ |
|---|---|---|---|
| `ready`（或 `draft`） | `in_field` | 派出 | 前置拒絕條件未决 |
| `in_field` | `returned` | 結算歸來（含賺／賠） | 強制結算條件未决 |
| `returned` | （新契約）`ready` | 再派＝新契約實例，非改寫舊結果 | 建議如此；是否允許同契約重開：未决 |
| `returned` | `archived` | 撤回／停用此配置之展示收斂 | 撤回語意未决 |

### 明確未决之轉移
- 經營者中途取消（`in_field` → 取消態）：做／不做未决
- 引擎失敗態是否獨立於 `returned`：未决（見待填表）
- 同一 Agent 可否並行多契約：未决（第一版建議否，仍待 lock）

## 4. 戰報／BattleResult（正式結果結構骨架）

### 角色
`BattleResult`＝單次出征的**正式結果**。結算後寫入戰績牆／履歷。  
模擬過程中的暫態數字**不是**正式結果。

### 建議結構骨架（未 lock）
| 區塊 | 用途 | 建議內容方向（非定稿欄位表） |
|---|---|---|
| 身份 | 誰、哪次契約 | 結果 id、契約 id、agent、empire、時間 |
| 模擬源 | 可稽核重播 | 見 §6；必須可指向同一重播鍵 |
| 績效 | 可說的數字 | 金額變動、報酬率、回撤、交易次數等（單位未决） |
| 結局態 | 正常結算 vs 失敗類 | 枚舉未决；虧損仍可為「正式結果」 |
| 歸因 | 最低可稽核 | 決策／約束／策略版本之引用；深度未决 |
| 證據 | 不可變錨 | `evidence_id`；與契約對齊 |

### 模擬 vs 正式結果邊界
| | 模擬過程 | 正式結果 |
|---|---|---|
| 可否進戰績牆主列 | 否 | 是（通過結算閘） |
| 可否當成長證據 | 否 | 是（且須可稽核） |
| 標示 | 過程 UI 可顯示「模擬中」 | 必須標模擬源；禁止暗示真資 |
| 改寫 | 過程暫態可丟 | 正式列資料層禁止洗白（§5） |

禁止：Agent 自報績效當正式結果；無模擬源之數字當正式結果。

---

## 5. 不可洗白（D5）

### 資料層（禁止）
- 刪除或覆寫歷史正式戰績／失敗紀錄
- 賽季或活動重置清空履歷
- 事後把虧損改為「未發生」或改寫金額／結局態
- 用展示文案覆蓋資料真相（展示可柔，資料不可偽）

### 展示層（允許）
- 排序、篩選、摺疊、摘要標籤
- 敘事語氣改寫（世界敘事負責），但必須仍可點回真實數字與結局
- 「精選」視圖；精選不得隱藏「失敗仍存在」的事實入口

### 原則一句
履歷變厚＝成長可見；失敗仍在。

## 6. 模擬源標示（D2、D3）

- 每次正式結果必須帶可稽核之 `simulation_source`（或等價結構）。
- 同重播鍵重放，正式績效數字必須一致；否則不得進戰績牆正式列。
- UI／戰報必須可見「模擬」標示；禁止默默當真資結果。
- 第一版自建模擬；不依賴 OKX 串接。OKX 對照文件僅機制參考，非本契約資料源。

---

## 7. 成長錨定（D4）

### 只允許
- 可稽核之正式 `BattleResult` 累積
- 履歷條目變多、失敗保留、策略版本可追溯

### 禁止
- 虛構 XP、憑空等級、與績效脫鉤之任務點數當核心成長
- 用未結算暫態或自報數字當成長證據

爭議時：數字若憑空而發，重做（底線原則）。

## 8. 驗收對照

### 對 D6／60 秒句／再派
| 檢查 | 規則側要支撐什麼 |
|---|---|
| 60 秒句成立 | 契約邊界清楚；派出→作戰中→歸來可辨；戰果有可說數字＋模擬標 |
| 自願再派 | `returned` 後可開新契約再派；或明確撤回；決策落在續用／撤回 |
| No-go | 僅演示可跑、像工具箱、像跟單圍觀、無再派意願 → 規則不得為了「跑通」放行假戰績 |

### 對五感驗收（規則相關列）
| 感 | 規則對照 |
|---|---|
| 任命感 | 契約綁 `agent_id`＋策略版本；非參數面板主路徑 |
| 出征感 | 狀態機至少「在外／已歸」可辨 |
| 戰報感 | 正式結果績效語彙＋模擬源 |
| 履歷感 | 戰績牆保留至少兩次；失敗不可洗 |
| 再派感 | 歸來後合法下一步＝再派（新契約）或撤回 |

本檔為草案，**不可單獨當驗收依據**；驗收由產品主編依 D6 判決。
