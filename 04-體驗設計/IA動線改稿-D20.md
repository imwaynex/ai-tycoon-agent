## 3. 關鍵路徑 ASCII＋禁止路徑

### 3.1 首次派出

```
任命席完成任命
    │  F1 auto
    ▼
大將已就位（可見改打法次級；勿搶）
    │  可選：點「改打法」→ L2 儲存 → 回大將
    ▼
去派出 ready（薄導覽或 auto）
    │
    ▼
只選期間 → 派出 → in_field
```

### 3.2 歸來／撤回後「調→再派」

```
歸來 或 in_field 撤回→立刻結算
    │
    ▼
戰報（主＝再派；弱＝先改打法）
    │           │
    │           └── 弱 CTA → 大將（結果摘要＋改打法）
    │                              │ 可選改打法並儲存
    │                              ▼
    └──── 再派 ──────────────────► 派出 ready（只選期間）→ 派出
```

沿用打法者：戰報直接「再派」，或大將次級「直接再派／去選期間」——**不强迫必改**。

### 3.3 禁止路徑

- 派出選期間 → 改打法／NL → 同屏派出  
- 戰報 → 直接修改或儲存策略／NL  
- 出征中 → 修改策略（含從角色側繞入）  
- 撤回尚未結算 → 調策略或再派  
- 「儲存打法並派出」一次提交兩種語意  
- 再派必須先重新任命；或文案暗示「只能重新任命才能換打法」  
- 選週期屏邊選邊調  
- 改打法後覆寫、隱藏或重新歸因既有戰報／撤回身分  
- 把戰報主 CTA 換成「回大將準備再派」取代「再派」  
- 大將已就位把「前往派出」做成搶 F1 的主 CTA

## 4. 歸來後「調→再派」UI 解（兩站）

建議把引導分成兩站：**戰報負責弱導回大將**；**大將負責看見並修改打法**；**再派＝新建選期**。

| 位置 | 直屏排列／文案槽 | CTA 層級與行為 |
|------|------------------|----------------|
| 戰報首屏 | 狀態 → 本次結果摘要 → 結果／證據 | **不放**策略操作本體 |
| 戰報操作區 | Mater：`想換打法？回大將那邊改。` | **主**＝再派（`redispatch`）；**弱**＝先改打法（`go_adjust_then_dispatch`）→ 回大將，**不**自動進編輯 |
| 大將歸來態 | 結果摘要 → 目前打法卡／改打法次級 | 改打法可見可操作；次級可「直接再派／去選期間」；勿强迫必改 |
| 大將改打法 L2 | Mater §3 整段 | 唯一提交＝儲存打法；返回不儲存；調完導出：去選出征多久再派出 |
| 派出 ready | 標題 → 期間 → 底部 | 唯一提交＝派出；**✂ 無改打法** |

補充：

- 「改打法」「去派出／再派」皆為導覽；實際提交分別在改打法層與派出屏。  
- 不依「損益不佳」新增判定門檻；所有已結算歸來態可提供相同入口。  
- 「打法已定／已更新」只確認儲存，不宣稱表現改善。  
- 不可達時不跳轉；依既有規則顯示原因。

- **待 Cruz lock：**歸來／撤回已結算的大將可調整後再派，也可沿用打法再派，兩者皆不以重新任命為前置。

## 7. Anti-jobs

- 不重做 D18 全案；只收斂策略屏位與再派銜接。  
- 不增加策略種類、Skill 能力、商業範圍或成效承諾。  
- 不把派出頁、戰報或出征中變成策略工具箱。  
- 不新增即時盯盤、OKX 或真資主依賴。  
- 不把重新任命包裝成唯一的策略優化方式。  
- 不以改策略洗掉虧損、撤回或其他歷史證據。  
- 不自動判定使用者「應該改打法」，也不自動代改。  
- 不發明假數據／假指標／擴大商業範圍。  
- 不開獨立參數工廠全屏為必做（對齊 D14）。

## 8. 待測假設（清晰度／再派意願分開）

| 類別 | 待測假設 | 測試方式／觀察槽 |
|------|----------|------------------|
| 清晰度 | 使用者知道調打法在大將側，派出頁只選期間 | 任務：「這次結果不如預期，請調整後再出征。」觀察首次點擊、是否誤找派出／戰報；[成功標準待填] |
| 清晰度 | 戰報弱「先改打法」足以導回大將策略區 | 觀察能否到達對應大將並指出改打法入口；[成功標準待填] |
| 清晰度 | 使用者分得清儲存打法與正式派出 | 儲存後詢問「現在是否已出征？」；[正確理解標準待填] |
| 再派意願 | 結果摘要緊接策略區，能形成下次出征理由 | 詢問是否願意再派及原因；[意願判讀方式待填] |
| 再派意願 | 保留「沿用打法／直接再派」避免不想修改者中斷 | 觀察沿用路徑選擇理由與完成情況；[判讀標準待填] |

**清晰度與再派意願分開判讀：**找到入口不代表願意再派；願意再派也不代表理解策略何時生效。
